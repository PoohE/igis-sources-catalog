## 1. Назначение документа

Документ содержит практические предложения по созданию унифицированной системы каталогизации историко-географических источников для построения иерархических исторических ГИС (ИГИС) Европейской части России.

**Охват архивов и информационных ресурсов** (синхронизировано со справочником «Архивы» в Notion, раздел «📚 Справочники каталога ИГИС»):
- **Федеральные архивы:** РГИА (С.-Петербург), РГАДА (Москва), РГВИА (Москва), ГАРФ (Москва), СПбФ АРАН (С.-Петербург)
- **Федеральные библиотеки и цифровые собрания:** РГБ (Москва), РНБ (С.-Петербург), ГПИБ (Москва), Президентская библиотека им. Б.Н. Ельцина (С.-Петербург), Национальная электронная библиотека — НЭБ
- **Порталы и агрегаторы:** Читальный зал Росархива (online.archives.ru), Яндекс.Поиск по архивам, Электронная библиотека исторических документов (ИнфоРост)
- **Региональные архивы:** ГАСО (Смоленск), ГАПК (Пермь), ГАЯО (Ярославль), ГАКО (Калуга), ЦГА Москвы
- **Региональные библиотеки:** Пермская краевая — ПГКБ, Смоленская — СОУНБ, Калужская — КОНБ, Ярославская — ЯОУНБ, Свердловская — СОУНБ (Екатеринбург)

**Иерархия ГИС:** губерния → уезд → волость

**Хронологический охват:** XVII — начало XX века

## 2. Система полей описания источника

Каждый источник описывается четырьмя блоками полей (74 поля: 73 со сквозной нумерацией + поле 14а). Минимальный профиль — Блок I (обязательный). Цифровой профиль — все четыре блока (Блок IV заполняется только при наличии цифровой копии).

> Служебные поля записи (авто-идентификатор `Шифр записи`, порядковый `№ п/п`, дата и автор внесения, год проверки) ведутся базой автоматически и в таблицу полей не включены.

### 3.1 Классификация источников

**Таблица 7. Классификация историко-географических источников**

Трёхчастное деление (A/B/C) — предложение авторов, опирающееся на источниковедческую типологию
исторических источников — картографические (изобразительно-графические) / письменные (текстовые) /
статистические (Данилевский и др., 1998) — и на концепцию **массовых источников** И.Д. Ковальченко
(Ковальченко, 1979), обосновывающую класс C. DC Type присвоен по международному словарю DCMI Type
Vocabulary. Для класса C применяется тип `Dataset` (DCMI: «данные в определённой структуре»), поскольку
серийные статистические источники представляют собой структурированные повторяющиеся записи, пригодные
для количественного анализа. C1 содержит смешанный состав: планы дач (`StillImage`) и экономические
примечания (`Text`); в качестве серийного массива классифицируется как `Dataset`.

> **A3 vs C1 — одно и то же, но на разном уровне описания.** *Межевые планы* (A3, `StillImage`) —
> отдельный план дачи как единичный картографический объект (единица описания — лист; для геопривязки
> и векторизации). *Материалы Генерального межевания* (C1, `Dataset`) — сплошной серийный массив планов
> вместе с экономическими примечаниями (единица — серия; для массового статистического анализа
> землепользования). Различие не в документе, а в единице описания.
>
> **Зачем в классификации B5 (путеводители по фондам).** Это не первичный источник, а
> справочно-навигационный: путеводитель описывает состав фондов и описей архива и служит точкой входа,
> без которой исследователь не обнаружит нужные картографические и статистические материалы. В каталоге
> как исследовательском инструменте он необходим.

### 3.3 Серийные массивы как Большие данные

Класс C — серийные исторические источники — представляет особую ценность для геостатистического анализа: однотипные записи по единой методике позволяют строить сопоставимые пространственные датасеты. По классификации DCMI Type Vocabulary все массивы класса C отнесены к типу **`Dataset`**. Картографические серии (трёхвёрстка, двухвёрстка, карта Стрельбицкого) формально принадлежат к классу A (`StillImage`), однако в контексте серийного массива их следует документировать как `Dataset` — на уровне серии в целом, сохраняя `StillImage` для отдельного листа.

Серийные массивы вынесены в **отдельный справочник** (реестр серий), а не только поединично, по трём
основаниям: (1) источниковедческое — массовые источники в смысле Ковальченко ценны как совокупность,
а не единица; (2) архивно-описательное — ISAD(G) выделяет самостоятельный уровень «серия» (фонд → серия →
дело → единица), которого нет в поединичном каталоге; (3) аналитическое — для многолистовых серий единицей
анализа служит покрытие целиком (сборка бесшовной мозаики, оценка полноты охвата). Справочник **связан со
справочником «Геопорталы»** (relation): оцифрованные серийные покрытия обычно публикуются на геопорталах
цельными слоями — запись серии ведёт напрямую к доступному ресурсу.

### 4.1 Десктопные и облачные инструменты

**Рекомендуемый стек для начала работы:**
1. **Ведение каталога:** Airtable или NocoDB (три связанные таблицы: Источники / Архивы / Проекты)
2. **Пространственная работа:** QGIS (геопривязка, векторизация; данные из каталога через CSV-импорт)
3. **Публикация:** Zenodo + Datasette

**Как организовать четыре блока полей в Airtable / Notion:**
- Создать одну главную таблицу «Источники» с 74 полями (четыре блока)
- Блок IV (оцифровка) активировать только для записей с цифровой копией — остальные строки оставить пустыми
- Связать со справочными таблицами: «Архивы», «Типы источников», «Современные регионы», «Серийные массивы» и др.
- Поля Блоков III и IV с перечислением значений оформить как множественный выбор из справочника

### 4.3 Рабочий процесс: от архива до публикации

```
ШАГ 1. Обследование архивного фонда
   → Заполнение минимального профиля (поля 1–28) в Airtable / Notion
   → Фотофиксация или запись архивных шифров

ШАГ 2. Описание физических характеристик
   → Дополнение Блока II (поля 29–42)
   → Первичная оценка масштаба и проекции

ШАГ 3. Получение цифровых копий
   → Заказ сканов в архиве или съёмка
   → Заполнение Блока IV (поля 56–73): год, исполнитель, DPI, цветность, формат файла
   → Обновление поля «Цифровая копия» (поле 17) — URL или путь к файлу

ШАГ 4. Геопривязка и векторизация
   → Работа в QGIS
   → Заполнение Блока III (поля 43–55): типы объектов, возможность векторизации
   → Обновление Блока IV (поля 64–72): тип привязки, СК, GCP, RMSE, форматы результата

ШАГ 5. Контроль качества
   → Проверка обязательных полей (минимальный профиль)
   → Верификация архивных шифров и дат

ШАГ 6. Экспорт для публикации
   → Экспорт из Airtable/NocoDB в CSV + JSON
   → Создание GeoJSON с bounding box каждого источника
   → Формирование README с описанием полей и лицензии

ШАГ 7. Публикация на Zenodo / Harvard Dataverse
   → Загрузка ZIP-архива (CSV + GeoJSON + README)
   → Заполнение метаданных репозитория
   → Получение DOI

ШАГ 8. Версионирование
   → При обновлении данных — новая версия записи с новым DOI
   → Старые версии сохраняются и остаются доступными
   → DOI текущей версии указывается в публикациях
```

## 5. Технические рекомендации

### 5.1 Форматы хранения

**Таблица 13. Рекомендуемые форматы**

| Назначение | Рекомендуемый формат | Альтернатива |
|------------|----------------------|--------------|
| Таблица каталога | CSV (UTF-8) | XLSX |
| Пространственный охват источников | GeoJSON | GeoPackage (.gpkg) |
| Метаданные набора данных | JSON-LD (schema.org/Dataset) | Dublin Core XML |
| Растровые цифровые копии карт | GeoTIFF (с геопривязкой) | JPEG2000 |
| Векторные слои | GeoPackage или Shapefile | GeoJSON |

### 5.2 Структура уникального идентификатора

Формат: `[АРХИВ]-Ф[НОМЕР]-О[НОМЕР]-Д[НОМЕР]-Л[НОМЕР]`

Примеры:
- `RGADA-F1355-O1-D1234-L5` — план дачи из фонда Генерального межевания РГАДА
- `RGVIA-VUA-O1-D6578-L1` — лист трёхвёрстки из Военно-учёного архива
- `GAPK-F65-O1-D890-L3` — карта из Пермского архива

### 5.3 Версионирование записей каталога

Каждая запись должна содержать служебные поля:
- `date_created` — дата создания записи
- `date_modified` — дата последнего изменения
- `created_by` — автор записи
- `modified_by` — автор изменения
- `version` — номер версии записи
